서울과학기술대학교 eClass 크롤러 실행 안내서
프로젝트: SeoulTechEclassUnityLite (C# / Unity 연동용)
============================================================

1. 프로그램 개요
------------------------------------------------------------
- 목적: eClass의 할 일과 공지사항을 조회하여 텍스트 파일로 저장
- 출력 파일: result.txt
- 출력 형식:

  [todo]
  할 일 1
  할 일 2
  [note]
  공지사항 1
  공지사항 2

- 특징: Playwright 및 Chromium 설치 불필요. HTTP 요청으로 데이터 조회.
- 로그인 방식: 브라우저에서 최초 로그인 후 쿠키를 수동 등록하고 재사용.
- 주의: 쿠키가 만료되면 다시 등록해야 함.

2. 최초 실행 준비 (VS Code / Windows)
------------------------------------------------------------
① SeoulTechEclassUnityLite.zip 압축 해제
② VS Code에서 SeoulTechEclassUnityLite.csproj 파일이 있는 폴더 열기
③ VS Code 터미널(PowerShell) 실행
④ 다음 명령어로 빌드:

  dotnet build

※ 빌드하려면 해당 프로젝트를 지원하는 .NET SDK가 설치되어 있어야 함.
※ '빌드 성공' 메시지가 나오면 다음 단계로 진행.

3. 샘플 HTML 테스트 (인터넷 로그인 불필요)
------------------------------------------------------------
프로젝트 폴더에서 아래 명령어 실행:

  dotnet run -- sample ".\Samples\sample.html"

확인 사항:
- sample_result.txt 파일이 생성되는지 확인
- 파일 안에 [todo], [note]와 추출된 항목이 있는지 확인

직접 저장한 eClass 로그인 후 HTML도 테스트 가능:

  dotnet run -- sample "C:\경로\outerHTML.txt"

※ 폴더명은 Sample이 아니라 Samples임.
※ sample_result.txt는 샘플 테스트 결과이며 실제 크롤링 결과는 result.txt임.

4. 실제 eClass 로그인 쿠키 등록 (최초 1회)
------------------------------------------------------------
① Chrome 또는 Edge로 다음 사이트 접속 후 직접 로그인:

  https://eclass.seoultech.ac.kr/ilos/main/main_form.acl

② 로그인 후 F12 → Network(네트워크) 탭으로 이동
③ Ctrl + R로 페이지 새로고침
④ 요청 목록에서 main_form.acl 선택
⑤ Headers → Request Headers → Cookie 항목의 '값' 복사
⑥ VS Code 터미널에서 다음 명령어 실행:

  dotnet run -- login

⑦ 터미널의 Cookie 입력 안내가 나오면 복사한 쿠키 값을 붙여넣고 Enter

확인 사항:
- 로그인 쿠키가 session_cookies.txt에 저장되는지 확인
- 쿠키는 로그인 비밀번호에 준하는 민감한 인증 정보이므로
  GitHub에 올리거나 팀원에게 공유하지 말 것.

5. 실제 할 일 / 공지사항 크롤링
------------------------------------------------------------
터미널에서 다음 명령어 실행:

  dotnet run -- crawl

확인 사항:
- 프로그램이 할 일 및 공지사항의 수집 개수를 출력하는지 확인
- 프로젝트 폴더에 result.txt가 생성되는지 확인
- result.txt 내용이 실제 eClass 화면과 일치하는지 비교

PowerShell에서 결과 내용 확인:

  Get-Content -Encoding utf8 .\result.txt

※ 실제 eClass에 항목이 있는데도 '0개'로 출력된다면
  인증 상태 또는 HTML 추출 규칙을 점검해야 함.
※ 현재 구현은 메인 화면의 할 일 및 공지사항을 대상으로 하며,
  과목별 강의실의 공지사항 전체 수집 기능과는 구분됨.

6. 두 번째 실행부터 (쿠키 재사용)
------------------------------------------------------------
이미 쿠키를 등록했다면 다시 로그인할 필요 없이 다음만 실행:

  dotnet run -- crawl

- 정상적으로 result.txt가 갱신되면 쿠키 재사용 성공.
- 로그인 세션이 만료되어 요청이 실패한다면 4번의 쿠키 등록을 반복.
- 쿠키 저장 파일은 컴퓨터마다 개별적으로 관리해야 함.

7. Unity 프로젝트에 연결하기
------------------------------------------------------------
① Unity 프로젝트의 Assets/Scripts 폴더에 다음 파일 추가:

  Shared/EclassCrawler.cs
  Unity/EclassUnityBridge.cs

② Unity에서 EclassUnityBridge 스크립트를 사용하여 기능 연결:
- OpenLoginPage(): 학교 로그인 페이지 열기
- ImportSessionCookie(string): 쿠키 등록
- FetchAndSave(): 데이터 조회 후 result.txt 저장

③ Unity 저장 위치는 프로젝트 설정에 따라 다르며,
   제공된 연동 코드에서는 Application.persistentDataPath를 사용함.

※ PC와 모바일에서의 실제 동작은 각각 테스트 필요.
※ Unity WebGL에서는 현재 방식의 직접 HTTP 수집에 제약이 있어
  별도 설계/검증이 필요함.

8. 자주 발생하는 문제
------------------------------------------------------------
[문제] dotnet run 시 애플리케이션 제어 정책이 .exe 실행을 차단함
- Windows 보안 정책에 의한 차단일 수 있음.
- 보안 기능을 무작정 끄기보다 차단 정책 및 실행 파일 출처 확인 권장.
- 우회 실행 점검(빌드 후 DLL 직접 실행):

  dotnet ".\bin\Debug\net10.0\SeoulTechEclassUnityLite.dll" sample ".\Samples\sample.html"

[문제] 파일/경로를 찾을 수 없음
- 현재 터미널 위치가 .csproj 파일이 있는 폴더인지 확인
- Samples 폴더 이름과 경로의 철자 확인

[문제] crawl 실행 시 로그인 오류 또는 결과가 비어 있음
- 쿠키가 유효한지 확인하고 필요 시 4번 과정 재진행
- 브라우저 화면의 실제 목록과 결과를 비교
- eClass 사이트의 구조가 바뀌면 추출 코드 수정이 필요할 수 있음
