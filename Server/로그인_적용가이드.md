# 기존 Server에 로컬 테스트 로그인 기능 추가

이 패치는 **기존 Server 폴더에 파일을 추가**합니다. `app/main.py` 전체를 교체하지 않습니다.

## 구현 범위

- `POST /v1/auth/login`: 앱 자체 학번과 비밀번호 확인, Access JWT와 Refresh Token 반환
- `POST /v1/auth/refresh`: Refresh Token 일회성 교체 및 Access Token 재발급
- `POST /v1/auth/logout`: Bearer Access Token이 속한 세션 폐기, 본문 없는 HTTP 204
- SQLite `data/auth.sqlite3`에 테스트 계정과 세션 저장 (처음 로그인 요청 시 자동 초기화)
- 개발용 로그인 실패 횟수 제한: IP+학번당 60초에 실패 5회, 동일 IP 전체 20회
- 비밀번호는 PBKDF2-SHA256 + 무작위 salt 해시로 저장, Refresh Token은 SHA-256 지문만 저장
- eClass 로그인/연동 코드는 **일절 변경하지 않음**

## 테스트 계정

| 구분 | 값 |
|---|---|
| 계정 이름 (DB에만 존재) | `test` |
| `studentId` (로그인 ID) | `20241234` |
| `password` | `Test1234!` |
| `role` | `user` |
| `isNewUser` | `true` (캐릭터 미생성 상태) |

학번은 명세의 필드에 맞춘 **테스트 전용 임의 학번**이며 학교 계정과 아무 관계가 없습니다.

## 기존 서버에 설치 (Windows + VS Code)

1. `Server` 폴더를 다른 이름으로 복사해 백업합니다.
2. ZIP을 **기존 `Server` 폴더의 상위 폴더**에서 풉니다. ZIP 안의 `Server/app/...` 경로가 기존 폴더에 병합됩니다. (기존 파일 덮어쓰기는 하지 않음)
3. VS Code에서 **기존 `Server` 폴더**를 엽니다. 터미널에서 다음을 실행합니다.

```powershell
python auth_install.py
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

`auth_install.py`는 `app/main.py` 맨 아래쪽에 라우터 등록 두 줄을 추가합니다. 수정 전에 `main.py.backup-before-auth-...` 자동 백업을 만듭니다. 기존 라우터는 건드리지 않습니다.

4. 브라우저에서 `http://127.0.0.1:8000/docs`를 열고 `POST /v1/auth/login` → `Try it out` → `Execute`를 선택합니다.

```json
{
  "studentId": "20241234",
  "password": "Test1234!"
}
```

**예상:** HTTP 200, `accessToken`, `refreshToken`, `expiresIn: 3600`, `isNewUser: true`, `role: "user"`.

5. 실패 확인: 비밀번호를 틀리게 입력하면 HTTP 401 + `INVALID_CREDENTIALS`. 연속 5회 실패하면 60초 이내 HTTP 429 + `RATE_LIMITED`.

### PowerShell 직접 호출

```powershell
$body = @{ studentId = "20241234"; password = "Test1234!" } | ConvertTo-Json
Invoke-RestMethod -Uri "http://127.0.0.1:8000/v1/auth/login" -Method Post -ContentType "application/json" -Body $body
```

### 자동 테스트

```powershell
python -m pip install pytest httpx
python -m pytest tests/test_auth.py -q
```

## 기존 소스와 연결되는 부분

- `app/api/v1/auth.py`: HTTP/API 계층 (`/v1/auth/*`)
- `app/services/auth_service.py`: 로그인/토큰 로직
- `app/repositories/auth_repository.py`: SQLite 읽기/쓰기
- `app/schemas/auth.py`: API 요청/응답 구조
- `app/core/auth_*.py`: 인증 보안/에러/시도 제한
- `data/auth.sqlite3`: 실행 시 생성되는 사용자 데이터베이스
- `data/auth_jwt_secret.key`: 실행 시 생성되는 JWT 서명 비밀키

**중요**: 기존 서버를 통째로 전달받지 못했으므로 현재 `app/main.py`가 `app = FastAPI(...)` 형태라는 조건으로 자동 등록기를 만들었습니다. 해당 형태가 아니라면 `app/main.py`에 아래 두 줄을 직접 추가합니다.

```python
from app.api.v1.auth import router as auth_router
app.include_router(auth_router)
```

## 향후 실제 배포 전 필수 조치

이 기본 계정과 비밀번호는 **개발 시연용**입니다. 인터넷에 공개하지 마세요. 배포 시 `AUTH_ENABLE_TEST_USER=0`으로 설정하고 데모 계정을 삭제하고, 사용자 가입·비밀번호 정책·관리자 권한·TLS·분산 레이트리밋을 별도로 구현하세요. `AUTH_JWT_SECRET`은 충분히 긴 임의의 비밀값으로 환경변수에 설정하거나 생성된 `auth_jwt_secret.key`를 안전하게 보관하세요. `data/` 파일을 Git에 커밋하지 마세요.

테스트 계정은 DB에 **처음 한 번만** 생성하며, 이미 존재하는 계정의 비밀번호는 재실행해도 바뀌지 않습니다.

향후 캐릭터 생성 후 `isNewUser`를 false로 바꾸려면 `auth_users.has_character`를 1로 변경하도록 캐릭터 생성 서비스를 연동해야 합니다.
