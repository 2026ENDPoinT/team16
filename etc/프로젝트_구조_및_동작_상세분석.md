# 짭마고치 (Zzapmagochi) 프로젝트 구조 및 코드 동작 상세 분석

> 작성일: 2026-11-14  
> 이 문서는 현재 Unity 프로젝트(`Zzapmagochi`)에 포함된 모든 C# 스크립트, 셰이더, WebGL 플러그인(`.jslib`), 에디터 자동화 도구가 **Unity 에디터의 어떤 오브젝트에 부착되어 어떻게 실행되고, 어떤 자료구조와 변수·함수를 통해 서로 호출·분기되는지**를 코드 수준에서 상세히 정리한 문서입니다.

---

## 1. 전체 실행 순서 및 씬(Scene) 분기 흐름

게임이 부팅(`BeforeSceneLoad`)된 시점부터 로그인/회원가입을 거쳐 설문(`scene_survey`) 또는 자취방(`scene_room`)으로 진입하기까지의 전체 호출 체인입니다.

```
[게임 부팅 (RuntimeInitializeLoadType.BeforeSceneLoad)]
  └─ MateProfileStore.RegisterSceneRedirectHook()
       └─ SceneManager.sceneLoaded += OnSceneLoaded 등록

[1. scene_login 진입]
  └─ LoginController.Awake() : 버튼 및 팝업 이벤트 리스너 연결
       ├─ (A) [로그인 버튼 클릭] LoginController.OnLoginClicked()
       │    ├─ await Api.Current.Login(id, pw)
       │    ├─ Session.Set(id, auth)  (※ auth.isNewUser = false)
       │    └─ LoginController.GoToRoom() -> SceneManager.LoadScene("scene_room")
       │
       └─ (B) [회원가입 버튼 클릭] SignUpPopup.Show()
            ├─ [중복확인 클릭] SignUpPopup.OnCheckIdClicked()
            │    └─ await Api.Current.CheckStudentId(id) -> _idChecked = true
            ├─ [회원가입 제출 클릭] SignUpPopup.OnSubmitClicked()
            │    ├─ await Api.Current.SignUp(id, pw)
            │    ├─ Session.Set(id, auth)  (※ auth.isNewUser = true)
            │    └─ SignedUp?.Invoke(id) -> LoginController.OnSignedUp()
            └─ LoginController.GoToRoom() -> SceneManager.LoadScene("scene_room")

[2. 씬 전환 가로채기 (MateProfileStore.OnSceneLoaded)]
  └─ 분기 조건 검사: (scene.name == "scene_room" && Session.IsNewUser && !_surveyCompletedForCurrentSession)
       ├─ 결과가 false (일반 로그인) ──► [scene_room] 그대로 유지 및 실행
       └─ 결과가 true  (신규 회원가입) ──► SceneManager.LoadScene("scene_survey") 즉시 호출!
                                            └─ [scene_survey] SurveyController 실행
                                                 ├─ 1단계: 인트로 패널
                                                 ├─ 2단계: 8문항 응답 (int[4] _scores 누적)
                                                 ├─ 3단계: 성격 판정 + 이름/말버릇(옵션) 입력
                                                 ├─ MateProfileStore.SaveSurveyResult(...)
                                                 └─ SceneManager.LoadScene("scene_room") -> 자취방 입주 완료!
```

## 2. Core & Net 계층 (데이터 · 세션 · 네트워크 기반)

씬이 전환되어도 메모리에 유지되는 `static` 클래스들과 비동기 API 통신 계층입니다.

### 2.1 `Api.cs`, `IApiClient.cs`, `MockApiClient.cs`
* **파일 경로**:
  * `Assets/Scripts/Core/Api.cs`
  * `Assets/Scripts/Net/IApiClient.cs`
  * `Assets/Scripts/Net/MockApiClient.cs`
* **유니티 에디터 부착 여부**: 오브젝트에 부착하지 않음 (`static` 서비스 로케이터 패턴).
* **핵심 변수 및 자료구조**:
  * `Api._current` (`IApiClient`): 기본값은 `null`이며, 외부에서 `Api.Current` 프로퍼티를 읽는 순간 `_current ??= new MockApiClient()`로 지연 생성(Lazy Initialization)됩니다. 추후 실서버 연동 시 `Api.Current = new HttpApiClient()` 한 줄만 교체하면 전체 호출부가 그대로 실서버와 통신합니다.
  * `MockApiClient.LatencyMs` (`int = 300`): 실제 네트워크 왕복을 흉내 내기 위해 `Task.Delay(300)`으로 0.3초 비동기 지연을 발생시킵니다.
  * `MockApiClient.RejectEverything` (`bool`): `true`로 설정하면 강제로 `ApiException`을 발생시켜 로그인/회원가입 실패 UI 팝업을 테스트할 수 있습니다.
* **메서드별 분기 규칙**:
  * `Login(string studentId, string password)`: `NewSession(isNewUser: false)`를 반환합니다.
  * `SignUp(string studentId, string password)`: `NewSession(isNewUser: true)`를 반환합니다. **(여기서 설정되는 `isNewUser = true`가 서베이 씬 분기의 핵심 키입니다.)**
  * `CheckStudentId(string studentId)`: 입력한 `studentId`가 `"taken"`으로 시작하면 `isAvailable = false`, 그 외에는 `true`를 담은 `IdAvailabilityResponse` 객체를 반환합니다.

### 2.2 `Session.cs`, `SceneNames.cs`, `ApiModels.cs`
* **파일 경로**:
  * `Assets/Scripts/Core/Session.cs`
  * `Assets/Scripts/Core/SceneNames.cs`
  * `Assets/Scripts/Net/ApiModels.cs`
* **유니티 에디터 부착 여부**: 부착하지 않음 (`static` 클래스 및 직렬화 DTO).
* **핵심 변수 및 구조**:
  * `Session` 클래스는 현재 로그인한 유저의 `StudentId`(`string`), `AccessToken`(`string`), `RefreshToken`(`string`), `Role`(`string`), `IsNewUser`(`bool`)를 정적 프로퍼티로 보관합니다.
  * `Session.Set(string studentId, AuthResponse auth)`가 호출되면 서버 응답 DTO(`AuthResponse`)의 필드들을 정적 프로퍼티에 복사합니다.
  * `ApiException` 클래스는 HTTP 상태 코드(`long StatusCode`)와 에러 코드 문자열(`string Code`, 예: `"INVALID_CREDENTIALS"`, `"STUDENT_ID_TAKEN"`)을 함께 담는 커스텀 예외 클래스입니다.

## 3. 로그인 & 회원가입 씬 (`scene_login.unity`)

이 씬의 모든 UI 계층 구조와 Inspector 참조 연결은 에디터 스크립트인 `Assets/Editor/LoginSceneBuilder.cs`의 `BuildAll()` 메서드가 자동으로 생성·연결합니다.

### 3.1 `LoginController.cs`
* **파일 경로**: `Assets/Scripts/UI/LoginController.cs`
* **에디터 부착 위치**: `scene_login` 씬의 `LoginController` 오브젝트.
* **Inspector 연결 변수 (`[SerializeField]`)**:
  * `idInput` (`TMP_InputField`), `passwordInput` (`TMP_InputField`)
  * `loginButton` (`Button`), `signUpButton` (`Button`)
  * `failPopup` (`MessagePopup`), `signUpPopup` (`SignUpPopup`)
  * 내부 상태 플래그: `private bool _busy` (통신 중 중복 클릭 방지용)
* **실행 순서 및 호출 흐름**:
  1. **`Awake()`**:
     * `loginButton.onClick.AddListener(OnLoginClicked)`
     * `signUpButton.onClick.AddListener(OnSignUpClicked)`
     * `signUpPopup.SignedUp += OnSignedUp` (회원가입 완료 시 호출될 C# `event Action<string>` 구독)
     * `signUpPopup.Failed += ShowFailure` (회원가입 에러 시 실패 팝업 호출 구독)
     * `passwordInput.onSubmit`에 엔터키 로그인 연결
  2. **`OnLoginClicked()` (`async void`)**:
     * `_busy`가 `true`이면 즉시 리턴. 아니면 `SetBusy(true)`로 모든 입력창과 버튼의 `interactable`을 `false`로 잠급니다.
     * `var auth = await Api.Current.Login(id, pw);` 호출.
     * 성공 시 `Session.Set(id, auth)` 실행 (`Session.IsNewUser = false`) 후 `GoToRoom()` → `SceneManager.LoadScene(SceneNames.Room)` 호출.
     * 실패(`catch (ApiException e)`) 시 `SetBusy(false)`로 잠금을 풀고 `ShowFailure(e.Message)` → `failPopup.Show(message, "로그인 실패")`를 호출해 팝업을 띄웁니다.

### 3.2 `SignUpPopup.cs` & `MessagePopup.cs`
* **파일 경로**: `Assets/Scripts/UI/SignUpPopup.cs`, `Assets/Scripts/UI/MessagePopup.cs`
* **에디터 부착 위치**: `Canvas` 하위의 `SignUpPopup` 오브젝트 및 `FailPopup` 오브젝트.
* **핵심 변수 및 상태 관리**:
  * `private bool _idChecked`: 아이디 중복확인을 통과했는지 여부.
  * `private string _checkedId`: 중복확인을 통과했을 때의 학번 문자열.
* **실행 순서 및 검증 알고리즘**:
  1. `OnCheckIdClicked()`에서 `await Api.Current.CheckStudentId(id)`를 호출해 `result.isAvailable == true`이면 `_idChecked = true`, `_checkedId = id`로 기록합니다.
  2. **중복확인 무효화 처리**: `idInput.onValueChanged`에 연결된 `OnIdChanged()`가 매 타이핑마다 실행되며, `_idChecked && idInput.text != _checkedId`인 경우(중복확인 후 글자를 고친 경우) 즉시 `_idChecked = false`로 되돌리고 `"아이디를 다시 확인해 주세요."` 경고 문구를 띄웁니다.
  3. **비밀번호 실시간 대조**: `passwordInput`과 `passwordConfirmInput`의 `onValueChanged`마다 `RefreshPasswordStatus()`가 호출되어 `pw == confirm` 여부를 검사합니다.
  4. **가입 버튼 활성화 조건 (`IsFormValid()`)**:
     ```csharp
     return _idChecked && !string.IsNullOrEmpty(pw) && pw == confirm;
     ```
     위 3가지가 모두 참일 때만 `submitButton.interactable = true`가 됩니다.
  5. **`OnSubmitClicked()`**:
     * `var auth = await Api.Current.SignUp(id, pw);`
     * `Session.Set(id, auth);` (**이 시점에 `Session.IsNewUser = true`가 저장됨**)
     * `SignedUp?.Invoke(id);` 이벤트를 발생시켜 `LoginController.OnSignedUp()` → `GoToRoom()`을 실행합니다.

## 4. 무충돌 서베이 분기 & 설문 씬 (`scene_survey.unity`)

팀원이 작업 중인 회원가입/로그인 파일(`LoginController.cs`, `SignUpPopup.cs`)을 단 한 줄도 수정하지 않고 **"로그인 → 룸 / 회원가입 → 서베이 → 룸"** 분기를 수행하는 구조입니다.

### 4.1 `MateProfileStore.cs`
* **파일 경로**: `Assets/Scripts/Room/MateProfileStore.cs`
* **에디터 부착 여부**: 부착하지 않음 (`static` 데이터 저장소 + 씬 로드 훅).
* **핵심 변수**:
  * `HasCustomProfile` (`bool`): 설문을 통해 프로필이 설정되었는지 여부.
  * `Nickname` (`string = "짭이"`): 설문에서 지정한 룸메이트 이름.
  * `Persona` (`MatePersonaType = MatePersonaType.Diligent`): 설문으로 판정된 성격(4종 중 1개).
  * `Catchphrase` (`string = ""`): 설문에서 입력한 말버릇(옵션).
  * `_surveyCompletedForCurrentSession` (`bool`): 현재 로그인 세션에서 이미 설문을 마쳤는지 여부(무한 루프 방지용).
* **자동 리다이렉트 원리**:
  1. `[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSceneLoad)]`가 붙은 `RegisterSceneRedirectHook()`이 게임 시작 시 `SceneManager.sceneLoaded += OnSceneLoaded`를 등록합니다.
  2. `LoginController.GoToRoom()`에 의해 `scene_room`이 로드되는 즉시 `OnSceneLoaded`가 실행됩니다.
  3. `Session.IsNewUser == true`(회원가입 직후)이면서 `_surveyCompletedForCurrentSession == false`이면 즉시 `SceneManager.LoadScene("scene_survey")`를 호출해 설문 씬으로 전환합니다.
  4. 일반 로그인(`Session.IsNewUser == false`)이거나 이미 설문을 마친 뒤(`_surveyCompletedForCurrentSession == true`)에는 리다이렉트하지 않고 그대로 `scene_room`을 진행합니다.

### 4.2 `SurveyController.cs` & `SurveySceneBuilder.cs`
* **파일 경로**:
  * `Assets/Scripts/UI/SurveyController.cs`
  * `Assets/Editor/SurveySceneBuilder.cs` (유니티 메뉴 `Zzapmagochi -> Build Scenes -> Build scene_survey`로 씬 자동 생성)
* **에디터 부착 위치**: `scene_survey` 씬의 `SurveyController` 오브젝트.
* **핵심 자료구조**:
  * `SurveyQuestion[] _questions`: 길이 8짜리 질문 구조체 배열. 각 `SurveyQuestion`은 질문 텍스트(`string questionText`)와 길이 4짜리 선택지 배열(`SurveyOption[] options`)을 가집니다.
  * `SurveyOption` 구조체: 보기 문구(`string text`)와 해당 보기가 점수를 부여할 성격 타입(`MatePersonaType targetPersona`)을 가집니다.
  * `private readonly int[] _scores = new int[4]`: 4가지 성격(`0: Diligent`, `1: Cheerleader`, `2: Tsundere`, `3: NightCoder`)의 점수를 누적하는 정수 배열입니다.
* **실행 및 성격 판정 알고리즘**:
  1. **`Start()` → `ShowIntroStep()`**:
     * `introPanel`만 켜고(`SetActive(true)`), `"작은 자취방에서 대학생활을 시작해봐요 / 룸메이트는 어떤 성격일까요?"` 화면을 보여줍니다.
  2. **`OnStartSurveyClicked()` → `RefreshQuestionUI()`**:
     * `Array.Clear(_scores, 0, _scores.Length)`로 점수를 0으로 초기화하고 `_currentQuestionIndex = 0`부터 첫 질문을 `questionText`와 `optionLabels[0..3]`에 출력합니다.
  3. **`OnOptionClicked(int optionIndex)`**:
     * 유저가 선택한 보기의 `targetPersona`를 읽어 `_scores[(int)persona] += 2`를 더합니다.
     * **동점 방지 가중치**: 8문항을 똑같이 2점씩만 주면 `4문항 : 4문항` 동점이 발생할 수 있으므로, 마지막 8번째 질문(`_currentQuestionIndex == _questions.Length - 1`)에는 `+1`점의 가중치를 추가해 반드시 단독 1위가 나오도록 처리합니다.
     * `_currentQuestionIndex++` 후 8문항이 모두 끝나면 `ShowResultStep()`을 호출합니다.
  4. **`ShowResultStep()` & `EvaluateWinningPersona()`**:
     * `_scores[0..3]` 중 최댓값을 가진 인덱스를 `(MatePersonaType)bestIndex`로 캐스팅해 최종 성격을 판정합니다.
     * `resultPanel`을 활성화하고 판정된 성격 제목(`resultPersonaTitleText`)과 설명(`resultPersonaDescText`)을 띄웁니다.
  5. **`OnEnterRoomClicked()`**:
     * `nicknameInput.text`(비어 있으면 `"짭이"`)와 `catchphraseInput.text`(말버릇 옵션, 비어 있어도 됨)를 읽어 `MateProfileStore.SaveSurveyResult(nickname, _judgedPersona, catchphrase)`에 저장한 뒤 `SceneManager.LoadScene(SceneNames.Room)`으로 자취방에 입장합니다.

## 5. 자취방 씬 (`scene_room.unity`) 내부 시스템 상세 해부

### 5.1 카메라 조작 컨트롤러 (`RoomCameraController.cs`)
* **파일 경로**: `Assets/Scripts/Room/RoomCameraController.cs`
* **에디터 부착 위치**: `scene_room`의 `Main Camera` 오브젝트.
* **핵심 변수**:
  * `originPosition` (`Vector3 = (1.88f, 3.6f, -1.88f)`)
  * `moveSpeed` (`float = 5f`), `zoomStep` (`float = 0.4f`), `minOrthoSize` (`1.5f`), `maxOrthoSize` (`7.0f`)
  * `_cam` (`Camera`), `_isDragging` (`bool`)
* **매 프레임 `Update()` 실행 순서**:
  1. **`HandleSpacebarReset()`**: `Keyboard.current.spaceKey.wasPressedThisFrame`이 감지되면 `transform.position = originPosition`으로 즉시 원점 복귀합니다.
  2. **`HandleWasdMove()`**: `W/A/S/D` 키 입력을 `Vector2 input`으로 합산하여 `new Vector3(input.normalized.x, input.normalized.y, 0f) * (moveSpeed * Time.deltaTime)` 벡터를 만들고, **`transform.Translate(localDelta, Space.Self)`** 를 호출해 기울어진 카메라 로컬 좌표계 기준으로 상·하·좌·우 이동합니다.
  3. **`HandleMouseDrag()`**: 마우스 좌클릭 드래그 중일 때 `mouse.delta.ReadValue()`로 프레임 간 픽셀 이동량 `pixelDelta`를 구합니다. Orthographic 카메라에서 화면 세로 전체 픽셀(`Screen.height`)은 월드 길이 `_cam.orthographicSize * 2f`와 같으므로, 1픽셀당 월드 길이 `unitsPerPixel = (_cam.orthographicSize * 2f) / Screen.height`를 곱해 `(-pixelDelta.x * unitsPerPixel, -pixelDelta.y * unitsPerPixel, 0f)`만큼 `Space.Self`로 이동시켜 마우스 커서와 바닥이 1:1로 맞물려 끌려오게 합니다.
  4. **`HandleMouseWheelZoom()`**: `mouse.scroll.ReadValue().y`의 부호(`Mathf.Sign`)에 따라 `_cam.orthographicSize` 값을 `zoomStep`만큼 증감시키고 `Mathf.Clamp`로 제한합니다.

### 5.2 3D 별 패턴 스카이박스 (`Skybox3DController.cs` & `Zzapmagochi3DSkybox.shader`)
* **파일 경로**:
  * `Assets/Scripts/Room/Skybox3DController.cs`
  * `Assets/Shader/Zzapmagochi3DSkybox.shader`
  * `Assets/Material/M_ZzapSkybox3D.mat`
* **동작 구조**:
  * `Skybox3DController.Awake()`는 원본 에셋 파일(`M_ZzapSkybox3D.mat`)의 값이 런타임에 변조되는 것을 막기 위해 `new Material(sourceMat)`으로 복사본 `_runtimeSkybox`를 생성해 `RenderSettings.skybox`에 할당합니다.
  * `Zzapmagochi3DSkybox.shader`의 프래그먼트 셰이더(`frag`)는 화면 정규화 좌표(`centeredUV`)로 중앙→외곽 보라색 비네팅 그라데이션을 그린 뒤, 카메라 월드 좌표 `_WorldSpaceCameraPos.xy * _PanParallax`와 회전각을 UV에 더하고 시간(`_Time.y * _ScrollVelocity.xy`)에 따라 `StarPattern.png`(`_PatternTex`)를 두 겹(메인 별 레이어 + 서브 작은 별 레이어)으로 샘플링해 흘러가는 별 배경을 그립니다.

### 5.3 캐릭터 파츠 정렬 및 걷기 애니메이션 (`CharacterParts.cs`)
* **파일 경로**: `Assets/Scripts/Character/CharacterParts.cs`
* **에디터 부착 위치**: 캐릭터 루트 오브젝트(`CharacterTemplate`).
* **핵심 자료구조**:
  * `CharacterPart` (`struct`): `public int order` (정렬 순서), `public Sprite parts` (스프라이트 에셋).
  * `CharacterBody` (`struct`): `outer`, `accessories`, `shoe_walk`, `shoe_idle`, `cloth_top`, `cloth_bottom_walk`, `cloth_bottom_idle`, `hair_front`, `hair_back`, `mouth`, `eye`, `leg_walk`, `leg_idle`, `arm`, `head`, `body` 총 16개의 `CharacterPart` 필드를 보유합니다.
  * `private readonly Dictionary<string, SpriteRenderer> _renderers`: 필드 이름 문자열(예: `"shoe_walk"`)을 Key로, 동적 생성된 자식 오브젝트의 `SpriteRenderer`를 Value로 저장하는 해시 테이블입니다.
* **실행 흐름**:
  1. `Start()`에서 `BuildParts()`와 `StartCoroutine(Walk())`를 호출합니다.
  2. `BuildParts()`는 `typeof(CharacterBody).GetFields(BindingFlags.Public | BindingFlags.Instance)` 리플렉션으로 16개 필드를 순회하며, 스프라이트가 할당된(`part.parts != null`) 파츠마다 자식 `GameObject`를 생성하고 `SpriteRenderer.sortingOrder = part.order + sortingOrderOffset`을 설정해 `_renderers` 딕셔너리에 넣습니다.
  3. `Walk()` 코루틴은 0.75초 간격으로 `SetWalking(true)`와 `SetWalking(false)`를 반복 호출합니다.
  4. `SetWalking(bool walking)`은 `_renderers`를 순회하며 Key가 `"_walk"`로 끝나는 파츠는 `renderer.enabled = walking`, `"_idle"`로 끝나는 파츠는 `renderer.enabled = !walking`으로 토글해 걷기 모션을 연출합니다.

### 5.4 3D 그리드 및 가구 배치 시스템 (`RoomGrid.cs`, `FurniturePlacementController.cs`, `FurnitureInventoryUI.cs`)
* **파일 경로**:
  * `Assets/Scripts/Room/FurnitureDefinition.cs` (`ScriptableObject` 데이터 정의)
  * `Assets/Scripts/Room/PlacedFurniture.cs` (배치된 가구 프리팹에 부착되는 컴포넌트)
  * `Assets/Scripts/Room/RoomGrid.cs` (3D 격자 점유 판정기)
  * `Assets/Scripts/Room/FurniturePlacementController.cs` (배치 상태 머신 및 마우스 피킹)
  * `Assets/Scripts/UI/FurnitureInventoryUI.cs` (오른쪽 인벤토리 UI 패널)
* **핵심 자료구조**:
  * `RoomGrid._occupied` (`Dictionary<Vector3Int, PlacedFurniture>`): 3차원 정수 격자 좌표 `(x, y, z)`를 Key로, 그 칸을 차지하고 있는 `PlacedFurniture` 참조를 Value로 저장하는 해시맵입니다.
  * `RoomGrid._placed` (`List<PlacedFurniture>`): 방에 설치된 전체 가구 목록입니다.
  * `FurniturePlacementController._previewRenderers` (`List<Renderer>`) & `_block` (`MaterialPropertyBlock`): 마우스를 따라다니는 반투명 프리뷰 가구의 렌더러 목록과 색상 제어용 프로퍼티 블록입니다.
* **실행 및 호출 체인**:
  1. 유저가 화면 좌측 상단 `가구 배치 모드` 버튼(`modeButton`)을 클릭하면 `FurnitureInventoryUI.OnModeButtonClicked()` → `FurniturePlacementController.TogglePlacementMode()` → `SetMode(Mode.Browsing)` 호출.
  2. `SetMode`가 `ModeChanged` 이벤트를 발생시키면 `FurnitureInventoryUI.OnModeChanged(Mode.Browsing)`가 호출되어 우측 인벤토리 패널(`inventoryRoot`)을 켭니다.
  3. 유저가 인벤토리에서 가구 버튼(예: 냉장고, 쇼파, 액자)을 누르면 `FurniturePlacementController.SelectFurniture(definition)`가 호출되어 프리팹을 복제한 `_preview` 오브젝트를 만들고(콜라이더 비활성화, 반투명 `previewMaterial` 및 `sortingOrder = 30000` 적용), 상태를 `Mode.Positioning`으로 전환합니다.
  4. `Mode.Positioning` 동안 매 프레임 `Update()` → `UpdatePreview()`가 실행됩니다:
     * `TryGetCellUnderPointer()`가 마우스 위치로 레이(`targetCamera.ScreenPointToRay`)를 쏩니다.
     * 바닥 가구(`PlacementSurface.Floor`)는 `y = 0` 바닥 평면(`Plane`)과 교차시켜 `(x, 0, z)` 칸을 구하고, 벽 가구(`PlacementSurface.Wall`)는 벽이 존재하는 면(`wallAtMinX`, `wallAtMaxZ`)의 평면과 교차시켜 가장 가까운 벽의 `(x, y, z)` 칸과 자동 회전 단계(`bestStep`)를 구합니다.
     * `grid.CanPlace(_selected, cell, _rotationStep)` → `grid.Validate()`가 호출되어 `EnumerateFootprint()`로 가구가 차지할 모든 `Vector3Int` 칸이 ① 격자 내부인지(`IsInside`), ② `_occupied` 딕셔너리에 이미 존재하는지(`ContainsKey`), ③ 바닥/벽 지지면이 있는지(`HasSupport`) 검사합니다.
     * 가능하면 초록색(`validColor`), 불가능하면 빨간색(`invalidColor`)을 `_block`에 넣어 프리뷰에 표시합니다.
  5. 가능한 위치에서 좌클릭하면 `ConfirmPlacement()` → `PlaceAt()`이 실제 가구 프리팹을 `Instantiate`하고 `grid.Occupy(placed)`를 호출해 `_occupied` 딕셔너리에 점유 칸들을 등록한 뒤 `Mode.Browsing`으로 돌아갑니다.

### 5.5 GitHub 스트릭 3D 전광판 가구 (`GitHubStreakFurniture3D.cs` & `GitHubStreakGenerator.cs`)
* **파일 경로**:
  * `Assets/Scripts/Room/GitHubStreakFurniture3D.cs`
  * `Assets/Scripts/Net/GitHubStreakGenerator.cs`
  * `Assets/Scripts/Net/GitHubStreakModels.cs`
* **핵심 자료구조**:
  * `GitHubStreakPayload`: `List<DayContribution> days` (365일 각각의 날짜 `date`, 커밋 수 `count`, 0~4단계 `ContributionLevel level`) 및 `currentStreak`, `longestStreak`, `totalContributions`를 담는 클래스.
  * `GitHubStreak3DBundle` (`IDisposable`): `Texture2D AlbedoTexture` (기본 잔디 색) + `Texture2D EmissionTexture` (커밋이 있는 칸만 빛나게 하는 자체 발광 텍스처) + `byte[] PngImageStream`.

  3. `Build3DBundleFromPayload()`가 `Color32[] albedoPixels`와 `Color32[] emissionPixels` 1차원 배열을 생성해 53주 × 7일 격자 위치마다 커밋 레벨 색상(`#0e4429` ~ `#39d353`)을 채워 넣은 뒤, `FilterMode.Point`가 적용된 두 장의 `Texture2D`로 구워냅니다.
  4. `ApplyBundleTo3DMesh()`가 `MaterialPropertyBlock`(`_mpb`)에 `_BaseMap`과 `_EmissionMap`을 세팅하여 액자 메쉬(`screenMeshRenderer`)에 적용합니다.

     * `pipTriggerButton`에 `EventTriggerType.PointerDown` 이벤트를 걸어 마우스를 누르는 즉시 `OpenDesktopMatePiP()`가 호출되게 합니다 (브라우저의 팝업 차단 정책인 `Transient User Activation`을 통과하기 위함).

     * `characterRoot` 하위의 모든 `SpriteRenderer[]`의 원래 레이어를 `int[] originalLayers`에 백업한 뒤, 잠시 `31`번 레이어로 옮깁니다.
     * `cullingMask = 1 << 31`, 배경색 `(0, 0, 0, 0)`인 임시 카메라(`__TempMateCaptureCam`)를 만들어 방의 벽이나 바닥 없이 캐릭터만 `RenderTexture`에 렌더링합니다.
     * `CharacterParts.SetWalking(false)` 상태로 `_cachedIdleTex` 1장, `SetWalking(true)` 상태로 `_cachedWalkTex` 1장을 `ReadPixels`로 찍은 뒤 즉시 원래 레이어로 복구하고 임시 카메라를 파괴합니다.
  3. **플랫폼 분기 (`#if UNITY_WEBGL && !UNITY_EDITOR`)**:
     * **유니티 에디터에서 실행 중일 때**:
       * `_editorMateActive`를 토글합니다.
       * 매 프레임 `Update()`에서 화면 하단 좌우 배회 좌표 `_matePosX`와 대사 타이머 `_mateSpeechTimer`를 계산합니다.

       * 유저가 캐릭터 영역(`charRect`)을 마우스로 클릭하거나 타이머 주기가 되면 `TriggerRandomLine()`이 호출되어 캐릭터 머리 바로 위에 흰색 말풍선(`GUI.Label`)을 5초간 띄웁니다.
     * **WebGL 빌드(PC 브라우저)에서 실행 중일 때**:
       * `_cachedIdleTex`와 `_cachedWalkTex`를 `EncodeToPNG()` → Base64 DataURL 문자열로 변환하고, 대사 리스트와 주기를 담은 JSON(`PiPConfigDto`)과 함께 `[DllImport("__Internal")]`로 연결된 `DesktopMatePiP.jslib`의 `ZzapDesktopMate_OpenPiP()`를 호출합니다.
